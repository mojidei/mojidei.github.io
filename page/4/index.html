flask:helloworld的404

复现

浏览器输入http://127.0.0.1:5000/hello ，回车，得到显示为“hello/”

探究

/hello相当于文件，/hello/相当于目录

看上去有时候浏览器会给地址最后自动加上/，原因不明。

注释掉/hello/后flash控制台的log

127.0.0.1 - - [18/Apr/2024 10:57:09] “GET /hello/ HTTP/1.1” 404 -

总之就是该访问/hello的时候莫名奇妙的访问了/hello/

解决

要么就是换个名字，要么就是把/hello里的东西塞进/hello/里。

自动更新hexo博客

大致原理

按照昨天的办法，现在有三个hexo仓库：客户端一个、/root/git/blog.git一个、nginx.conf部署的目录里一个。

使用crontab设置定时任务，每分钟拉取一次仓库。

为服务器root用户生成ssh密钥

谁都可以clone仓库，但要想pull，就得有密钥，否则就会报错：”Please make sure you have the correct access rights and the repository exists.”

生成密钥很简单

-C 后边跟的是注释哈，所以没写邮箱。一路回车下去，密钥就创建好了。接下来放进authorized_keys，允许它自己登陆自己。

另外，由于nginx.conf部署的目录里那个仓库“/usr/share/nginx/blog”权限需要root，而上次我们用的是别的用户创建的仓库……这就乱了，pull的时候还要输入密码。因此我把上次/home/oneday/git/blog.git删掉了，重新用root整。/usr/share/nginx/blog仓库也是一样。

创建脚本

vim blog2.sh

那个“/var/www/blog”是我真实环境里的目录，之前的/usr/share/nginx/blog是我虚拟机用的，可能有点乱。在这里这俩其实是一个东西，使用的目录也是唯一的。

添加执行权限

chmod +x blog2.sh

编辑定时任务

crontab -e

现在我们进入了一个文件，cron每分钟会看一下这个文件里面有没有需要执行的脚本。接下来我们添加一行

*/1 * * * * /root/sh/blog2.sh

这行的意思是，每分钟执行一次后面这个脚本。

完成了。即使不重启cron（centos里是crond），cron也会按照配置好的执行。

可能用到的

常见的定时任务问题包括：

  1. cron未启动
  2. 脚本没有执行权限
  3. 不是绝对路径
  4. 时差或linux时间与互联网时间不一致

博客里该写什么

这个是旧的博文重新放上来，时间只能精确到日期。。重新收录于24年4月26日

应该是沉淀

互联网有一个特点，就是共享。上面的绝大部分内容都不是只给某个人单独看的。所以，博客的内容更多的是给别人看的，让别人能够看懂，否则只会增加垃圾信息，让使用搜索引擎的人感到不适。

正因为如此，我不会把复习类的笔记发上来。因为笔记本来就不是写给别人看的，它是写给自己复习用的。这种东西别人很难看懂。

我以为，博客上只应有一种东西，那就是沉淀。或许是理解了某个新概念，学到了新东西，写一篇文章来介绍它。或者是做了某件事之后有什么新的感想，产生了新的东西，再或者遇到了棘手的问题，把解决问题的过程写下来。这些都可以称为沉淀。沉淀往往需要对事物有着相对长时间的接触才有。作为沉淀，往往是总结性的。深挖一个问题、将多个问题构成一个系列成为一个类型的问题……
